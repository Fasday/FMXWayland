# Native X11 fallback: scope and verification

This is initial X11 support in FMXWayland. The same Linux executable can use native Wayland or native Xlib;
neither GTK nor `libfmux.so` is required. `FMXWAYLAND_BACKEND=auto` prefers Wayland and selects X11 when Wayland
cannot be used at startup. `x11` and `wayland` force a backend. Existing windows do not migrate after a connection
is lost.

## Current scope

- Cairo/Pango and Skia **raster** canvases, including transparent popup padding (ARGB32 with a compositor,
  Shape clipping without one).
- Toplevels, popup input/grabs, text clipboard, modal forms/dialogs, timers and main-thread wake-ups.
- Custom title bars through the existing `IFMXWaylandWindowFrame` GUID. EWMH move/resize/maximize on modern WMs;
  pointer grabs and client geometry fallbacks on legacy WMs. A WM menu is exposed only if supported.
- One X screen at scale 1. No per-monitor RandR/HiDPI, XIM/IME, native drag-and-drop, GPU presentation or clipboard
  images. Window rectangles describe the client area. Without a compositor, transparency is binary (no soft shadow).
- Incoming clipboard transfers are bounded to 16 MiB / five seconds.

Runtime libraries: `libX11.so.6`, `libxkbcommon.so.0`, the chosen canvas's dependencies. ARGB visual discovery uses
`libXrender.so.1`; non-composited transparency uses `libXext.so.6`. All X libraries are loaded on demand on X11.

### Xming clipboard bridge

The public **Xming 6.9.0.31** in multiwindow mode passed the Hello/UI tests with Cairo and Skia. With `-clipboard`,
ordinary Windows-to-FMX ASCII/Unicode transfers worked, including a large Windows text. A reproducible failure
remains for a large xclip-to-FMX INCR transfer while the Windows clipboard bridge is active: empty text is returned.
The same native X11 transfer passes without `-clipboard`. The server stayed running during that failure.

This does not establish compatibility with every Xming version or with GPU rendering. The test runner disables
the Windows bridge by default. `-ClipboardBridge` reproduces the bridge configuration; use
`-SkipLargeClipboard` only deliberately (the suite reports that check as skipped).

## Verification (2026-10-20)

Checked from a clean HEAD-based worktree containing the X11 changes, with Delphi 13/Linux64, the Ubuntu 22.04
link SDK and Ubuntu 26.04 under WSL2:

| Environment | Cairo | Skia raster |
|---|---|---|
| Xvfb + Openbox, Shape and composited ARGB32 paths | PASS | PASS |
| Xorg 1.21.1.22, dummy DDX + Openbox, Shape and ARGB32 | PASS | PASS |
| Xming 6.9.0.31 multiwindow, Windows clipboard bridge off | PASS | PASS |
| Weston Wayland regression: scale 1/2, fonts, early popups, custom frames | PASS | PASS |

The X11 suite includes native/legacy frame operations, callback lifetime checks, clipboard INCR and screen resize
(private servers only). The Wayland suite covers 157 distinct assertions per canvas. Skia's scale-2 self-test
was repeated with a 40-second quit deadline: under parallel load the previous 25-second deadline could close the
program after the last dialog but before its final `done` tick. The completion assertion remains mandatory.

## Reproducible test matrix

On the WSL distribution used for tests (Ubuntu 26.04 by default):

```sh
sudo apt-get install xvfb openbox xcompmgr xdotool xclip x11-utils x11-xserver-utils imagemagick python3 \
  libxfixes3 libxrender1 libxext6 weston \
  xserver-xorg-core xserver-xorg-video-dummy
```

From Windows, with Delphi/Linux SDK configured as described in the main README:

```powershell
# Builds current Cairo/Skia Hello binaries and BackendCheck; isolates the X server from WSLg.
.\tests\x11-headless.ps1 -Server Xvfb
.\tests\x11-headless.ps1 -Server Xorg -SkipBuild

# A separately installed Xming. Authentication is generated per run and removed afterwards.
.\tests\xming.ps1 -XmingExe 'C:\Program Files (x86)\Xming\Xming.exe' -SkipBuild

# Required Wayland regression on the same binaries, including scale 1/2 and custom title bars.
.\tests\weston-headless.ps1 -BuildRoot D:\Work\FMXWayland-build\x11-release\cairo -Canvas TLinuxCanvas
.\tests\weston-headless.ps1 -BuildRoot D:\Work\FMXWayland-build\x11-release\skia -Canvas TSkRasterCanvas
```

`-BuildRoot`, `-Distro`, `-Canvas Cairo|Skia|Both` can be overridden. Xming's Windows-host address is detected from
the WSL NAT gateway; for mirrored networking, pass `-HostAddress 127.0.0.1` if appropriate. The server must be
reachable over TCP from WSL. The runner does not change firewall rules or install/download Xming.

For an already running **dedicated** X server:

```powershell
.\tests\x11-headless.ps1 -Server Existing -Display 172.27.16.1:92 -XAuthority C:\Temp\Xauthority -SkipBuild
```

Existing-server tests move the pointer and create windows. They do not replace the WM, modify `_NET_SUPPORTED`,
start a compositor or resize that server's screen. They preserve textual Windows clipboard contents. Tests on
private Xvfb/Xorg do exercise native and legacy frame operations, both composited and non-composited popup paths,
and a real root-screen resize. Each run records server information, logs/screenshots and a `PASSED` marker only
after all enabled checks succeed. Executables are copied to a fresh Linux inode before running to avoid stale
DrvFS mappings after Windows-side rebuilds.

`BackendCheck` additionally checks Xlib LP64 layouts, early clipboard-unit initialization, coordinate transforms
after WM reparent/frame movement and synthetic configure events, popup override-redirect at **creation**, window
destruction/recreation inside callbacks, and clipboard INCR. The `signal` probe also checks that writing to a
disconnected peer returns an I/O failure instead of terminating the X11 process with SIGPIPE.
`tests/xming-window.ps1` verifies native Win32
minimize/restore where Xming does not publish `WM_STATE`.

## Interactive Xorg desktop

Install `x11vnc` and a VNC viewer in addition to the packages above. From the repository on Linux:

```sh
# On WSLg, isolate its read-only /tmp/.X11-unix mount. Use absolute paths for both script and executable.
sudo unshare --mount bash tests/x11-private.sh "$PWD/tools/xorg-demo.sh" \
  /tmp/fmx-xorg-demo /absolute/path/to/Hello 91 5991
```

Connect a local VNC viewer to `127.0.0.1::5991`. The application uses the actual Xorg dummy DDX server, Openbox and
xcompmgr. VNC only carries the image/input; it is not the application's X server. Closing Hello stops the test
server and its helper processes. The Xorg log and `server-executable.txt` identify the server used. This verifies
Xorg protocol compatibility with a virtual screen, not a physical GPU/driver configuration.

For WSLg-native manual comparisons, move windows by dragging the title bar. Moving only the Windows RDP window
with `SetWindowPos` can desynchronize its position from the compositor.
